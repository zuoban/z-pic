# Z Pic

使用 MyGo 原生 UI 构建的本地桌面图片压缩工具，支持单张与批量处理 JPEG / PNG，不需要前端构建工具或图片处理服务。

## 使用

1. 选择单张图片进入单图模式；选择多张图片、选择文件夹或直接拖入多图 / 文件夹则进入批量模式（也可拖放追加到现有队列）。
2. 在主界面选择压缩方案。首次启动提供「体积优先 / 均衡 / 画质优先」，默认「均衡」；后续恢复上次选择。
3. 点击“开始压缩”，查看预览、输出大小和实际减少比例。
4. 单图模式下点击“另存副本”选择新文件名，或点击“覆盖原图”并确认替换，保存/覆盖成功后可直接点击「定位文件」在文件夹中查看结果；批量模式下可选择「保存到文件夹」或确认「覆盖原图」。

主界面只提供方案选择，不显示压缩参数。点击右上角「设置」打开独立的原生设置弹窗，在「压缩方案」中维护方案：

- 左侧选择方案查看或编辑：内置方案（体积优先 / 均衡 / 画质优先）为只读，不允许编辑或删除；自定义方案可在右侧修改名称、JPEG 质量及 PNG 参数。
- 点击「新增方案」添加命名方案；选中自定义方案时可点击「删除方案」并确认删除。
- 点击「保存」或按 `⌘S` / `Ctrl+S` 写入本地并生效，主界面同步更新方案列表。关闭应用后仍保留方案名称、参数及当前选择。
- 点击「取消」、关闭弹窗或按 `Esc` 放弃未保存修改。选图前也可以维护和选择方案。

仅打开或取消设置弹窗不会清除已选图片、压缩结果或预览对比状态；保存时仅当前方案的压缩参数发生实际变化才清除旧结果。重命名方案或编辑其他方案保留当前结果。

## 批量处理

- **导入队列**：在空视图或批量队列中点击「选择图片 / 添加图片」（可多选）、「选择文件夹 / 添加文件夹」（递归扫描，自动跳过隐藏目录/文件与符号链接，单队列最多 2000 张），或将多个文件与文件夹直接拖入窗口；已在批量队列中时拖入或添加会追加并去重。
- **输出方式**：
  - **保存到文件夹**（默认）：选择输出目录（配置有效时自动记住上次存在且可用的输出文件夹，新开批量队列时自动预填），按相对路径写入结果；若与原图同路径或目标已存在，自动追加 `-compressed`（及编号），绝不覆盖原图或已有文件。完成后可点击「打开输出文件夹」，或在选中项底栏/单张预览中点击「定位文件」直接定位单个输出文件。
  - **覆盖原图**：点击开始后弹出确认框，确认框默认选中「取消」；确认后按与单图相同的同目录临时文件 + 同步 + 原子替换流程写入。未减小的图片会自动跳过并保留原文件。
- **顺序执行、取消与恢复**：批量任务在后台逐张顺序压缩以控制内存占用。过程中可点击「取消操作」中断；已完成的项会保留结果，可点击「继续压缩」只处理剩余项，或点击「重新压缩」全部重跑。
- **队列筛选、搜索、排序与快速操作**：支持按状态切换「全部 / 待处理 / 已完成 / 失败」、按相对路径文件名搜索（`⌘F` / `Ctrl+F` 快速聚焦），以及按「默认顺序 / 按名称 / 原大小 ↓ / 节省率 ↓」排序（排序和筛选期间会保持当前选中项）；列表头会显示当前匹配数量，筛选为空时可点击「显示全部」一键重置。输入焦点不在文本框时可按 `Delete` / `Backspace` 快速移除当前选中项；结果摘要会同时显示已节省体积与未减小数量。
- **失败项重试与一键清理**：存在失败或无效图片时，队列顶部会显示失败提示栏——可点击「移除无效项」仅清理损坏/动画 PNG 等不可重试条目，或点击「移除失败项」清空队列中的全部失败条目（若当前正处于「失败」筛选且已无剩余失败项，会自动切回「全部」视图）；存在可重试的压缩/写入失败项时还会显示「重试失败项」，选中单条失败项或在其单张预览中也会显示「重试」按钮，仅重跑失败项并保留已完成项与待处理项（在「覆盖原图」模式下重试同样需要确认）。
- **单张对比预览**：在队列中点击「预览」或双击队列项（焦点在列表时也可按 `Enter`）进入单图「对比 / 原图 / 结果」预览，支持缩放与拖动对比，底部可查看失败原因或直接点击「定位文件 / 重试 / 移除」；点击「上一张 / 下一张」或按 `⌘[` / `⌘]`（`Ctrl+[` / `Ctrl+]`）会在当前筛选与排序结果内顺序切换；按 `Esc` 或点击「返回列表」回到队列。
- **失效保护**：切换压缩参数不同的方案、保存对当前方案参数的修改，或切换「保存到文件夹 / 覆盖原图」输出方式时，会清除已有的批量压缩结果，避免参数与结果不一致。

完成压缩后，预览区默认显示「对比」：左侧原图、右侧压缩后，显示各自文件大小。左右拖动分隔线查看画质变化，也可切换「原图 / 结果」单独查看。分隔线获得焦点后，方向键微调，`Home` 显示完整压缩结果，`End` 显示完整原图。

使用加减按钮（`⌘-` / `⌘=` 或 `⌘+`）、鼠标滚轮或触控板捏合缩放；「1:1」（`⌘1`）按原始尺寸查看，「适应」（`⌘0`）恢复完整图片。放大后双指滚动平移，单图模式也可拖动平移。三种模式共用缩放和位置，切换不会影响压缩结果或保存内容。重新压缩或更换图片后恢复居中对比和适应显示；覆盖原图后不再提供旧原图对比。

主界面常用快捷键：`⌘O` 选择或追加图片、`⌘Enter` 开始/继续或重新压缩、`⌘S` 在单图模式下另存副本（在批量「保存到文件夹」队列页用于选择输出文件夹）、`⌘,` 打开设置；批量队列页中 `⌘F` 聚焦文件名搜索、未聚焦文本输入时 `Delete` / `Backspace` 移除选中项；批量单图预览中 `⌘[` / `⌘]` 切换上一张 / 下一张、`Esc` 返回队列；单图或批量预览显示图片时 `⌘-` / `⌘=`（或 `⌘+`）/ `⌘0` / `⌘1` 缩放与恢复适应（其他平台使用 `Ctrl`，如 `Ctrl+,` 打开设置）。处理期间、设置弹窗与覆盖确认框打开时暂停主界面的快捷操作。设置弹窗打开时，主窗口暂停接收图片与压缩操作。

设置保存在系统用户配置目录的 `z-pic/settings.json`。macOS 默认位置为 `~/Library/Application Support/z-pic/settings.json`。首次启动无配置时使用默认方案；配置损坏时显示错误并暂用默认方案，不自动覆盖原文件；写入失败时保留旧文件和弹窗中的编辑内容。

输入限制为 64 MiB、3200 万像素。压缩不缩放图片，JPEG 会按 EXIF 方向规范化像素。结果未变小时保留原始数据并禁用覆盖。“另存副本”始终拒绝覆盖源文件或任何已有文件。JPEG 重新编码及 PNG 有损压缩可能改变或移除元数据。

“覆盖原图”需要单独确认，确认框默认选中“取消”；覆盖后无法通过本工具恢复原文件，不会自动生成备份。保存前会核对源文件与压缩输入是否一致，拒绝覆盖已被外部修改、已删除或指向符号链接的源文件；此时可以重新选图，或另存当前结果。覆盖成功后会更新图片内容快照，保留本次大小对比及另存功能，并禁用同一结果的重复覆盖。

压缩使用选图时的内容快照，外部修改原文件不会改变本次处理内容。正常关闭应用会等待已经开始的保存操作完成。

覆盖使用原文件所在目录的临时文件，完整写入并同步后替换，保留文件权限；不保留原 inode、属主、扩展属性或硬链接关系。当前 macOS 目标使用同目录原子替换；源文件校验与替换之间仍存在很短的并发修改窗口，不提供跨应用文件锁。写入或替换失败时清理临时文件并保留源文件。

PNG 使用 **pngquant 量化颜色，再由 Oxipng 优化输出**，不提供单独的无损模式。支持透明度和 8/16 位 PNG 输入，但输出颜色、位深、渐变、阴影与半透明边缘可能变化。达不到质量下限或没有体积收益时，不采用量化结果，保留较小且有效的数据。PNG 质量值是 pngquant 的内部评分，不是 JPEG 滑块值或“画质保留百分比”。

| 初始方案 | JPEG 质量 | PNG 最低–目标质量 | PNG 最大颜色数 | PNG 速度 |
| --- | ---: | ---: | ---: | ---: |
| 体积优先 | 60 | 40–65 | 128 | 3 |
| 均衡（默认） | 80 | 65–85 | 256 | 3 |
| 画质优先 | 92 | 85–100 | 256 | 1 |

JPEG 可调整质量（1–100）；PNG 可调整目标质量（1–100）、最大颜色数（2–256），展开「高级设置」可调整最低质量（0–目标质量）和处理速度（1–11，越大越快，但可能降低压缩效果）。降低目标质量时，最低质量会随之限制在有效范围内。减少颜色或降低质量通常能得到更小的文件，具体收益取决于图片内容。方案名称不能为空或重复，最长 40 个字符。

主界面切换到压缩参数不同的方案，或保存对当前方案参数的修改时，旧压缩结果会清除，并恢复原图预览，需要重新压缩才能保存。处理过程中禁止维护压缩方案。完成后显示原始大小、输出大小和实际减少比例；没有体积收益时明确显示“未减小（0.0%）”。工具执行失败时显示错误。

暂不提供 WebP、HEIC、AVIF、GIF、格式转换或调整尺寸。

## 开发

Go 模块要求 **Go 1.27.3 或更高版本**，MyGo 固定为 v0.9.0。支持自动工具链管理的 Go 安装会按需下载所需版本。

当前仓库内置 macOS ARM64 的 Oxipng **10.2.1** 与 pngquant **3.0.3**。该平台直接运行或打包即可，用户无需安装 Rust、Homebrew 或命令行优化器；运行过程中不下载工具。其他平台需要先准备对应系统与架构的原生工具，不能直接使用 macOS 二进制。

```sh
go mod download
go run .
```

也可在启动时直接传入单张图片、多张图片或文件夹：

```sh
go run . /absolute/path/to/photo.jpg
go run . /absolute/path/to/photo1.jpg /absolute/path/to/folder
```

使用 MyGo 的热重载开发：

```sh
go tool mygo dev
```

PNG 工具的固定版本、来源、许可证和重新构建方式见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)、[scripts/PNGTOOLS.md](scripts/PNGTOOLS.md) 及 [scripts/prepare-pngtools.sh](scripts/prepare-pngtools.sh)。仓库随附固定版本源码和依赖，脚本默认离线构建；开发者需要预先安装 Rust、C 编译环境及相应平台 SDK。应用正常压缩不需要这些开发工具或网络。

## 验证与打包

```sh
go test ./...
go test -race ./...
go vet ./...
go tool mygo vet
go tool mygo build -skip-dmg -skip-notarize -sign -
```

打包产物位于 `dist/`。以上命令在 macOS 使用临时签名生成本地运行的应用，不进行公证。第三方声明和许可证随资源一起打包。首个验证目标是当前开发环境 macOS ARM64；其他系统需准备对应原生工具，再分别进行原生窗口、文件对话框和安装包验证。

原生窗口端到端测试可使用只在 `e2e` 构建中启用的 MyGo automation 插件，正式构建不导入该插件：

```sh
go build -tags e2e -o build/z-pic-e2e .
MYGO_AUTOMATION=/tmp/z-pic-automation.sock ./build/z-pic-e2e
```

测试持久化时可设置 `ZPIC_CONFIG_FILE=/absolute/path/to/test-settings.json`，将配置读写隔离到指定文件；退出并重启应用后核对方案列表、参数和当前选择。

界面约定见 [DESIGN.md](DESIGN.md)。图片核心位于 `internal/compress`；原生工具执行、输出限制、超时与取消处理位于 `internal/pngtools`。JPEG 编码和图片输入/输出验证使用 Go 标准库，PNG 压缩使用捆绑工具；没有新增 Go 模块依赖。
