# Z Pic

使用 MyGo 原生 UI 构建的本地桌面图片压缩工具，支持单张与批量处理静态 JPEG / PNG / WebP，不需要前端构建工具或图片处理服务。

## 使用

1. 选择单张图片进入单图模式；选择多张图片、选择文件夹或直接拖入多图 / 文件夹则进入批量模式（也可拖放追加到现有队列）。点击顶部「粘贴图片」或按 `⌘V` / `Ctrl+V`，可将剪贴板中的截图、JPEG / PNG / WebP 图片或复制的图片文件加入批量队列；已有图片会保留，重复文件自动去重。无文件路径的剪贴板图片会先保存到「下载/Z Pic」，导入成功或失败均有浮动通知。在搜索框等文本输入区域，粘贴快捷键仍用于粘贴文字。
2. 打开右上角「设置」，在固定顶部的「当前预设」列表中选择预设，点击「保存」后使用。首次启动仅提供一个「均衡」默认预设；后续恢复上次选择，已有预设及参数继续保留。主界面「压缩概览」展示当前预设。
3. 如需调整参数，点击主界面当前预设旁的「编辑」，直接进入该预设的设置；也可在设置中点击「管理预设」或切换到「预设」。修改并保存后，点击主界面顶部操作栏的「开始压缩」查看预览、输出大小和实际减少比例。开始、继续及重新压缩操作统一位于顶部操作栏。
4. 单图保存按钮会明确显示「保存到原文件夹」「保存到预设目录」「选择位置并保存…」或「覆盖原图…」，保存方式卡片以当前图片展示文件名、后缀和适用的子文件夹。覆盖需要确认，结果未减小或已经覆盖时会显示原因并禁用重复覆盖。也可点击「另存副本」单独选择文件名。点击「复制图片」可将压缩结果复制到剪贴板并直接粘贴；批量任务中打开已完成图片的预览后也可复制。JPEG / WebP 以 PNG 图片写入剪贴板，保留显示方向和透明度，磁盘输出格式不变。批量任务按同一预设输出。保存或覆盖成功后可点击「定位文件」查看结果。

右上角「设置」或 `⌘,` / `Ctrl+,` 打开原生设置窗口，默认进入「通用」。两页共用固定顶部的「当前预设」选择器，列表标记当前选择；切换预设仅修改草稿，保存后才应用，取消时保留原有预设和压缩结果。顶部分类可切换到「预设」，切换时保留两页的未保存修改。

- 「通用」提供「跟随系统 / 浅色 / 深色」外观选择及常用快捷键说明；点击主题立即预览主窗口、设置及悬浮窗外观，保存后记住选择，取消或关闭时恢复原主题。也可点击「管理预设」进入预设页。
- 「管理预设」进入「预设」并编辑当前选择，布局沿用预设标签和分组卡片：

- 顶部标签选择编辑对象，「＋」新增预设；在「预设名称」输入框中可直接修改名称。所有预设均可编辑、复制或删除，至少保留一个。
- 「图片质量」提供六档，默认第 3 档「均衡质量」。JPEG / WebP 质量与 PNG 的质量范围、颜色数和处理速度随档位统一调整，不再提供独立的高级参数入口；旧配置的自定义数值在调整档位前保持不变。
- 「保存到」提供「原文件夹 / 每次询问 / 固定输出目录」；选择「原文件夹」或「固定输出目录」时均可勾选「保存到子文件夹」，默认名称为 `zpic`。选择「每次询问」时该设置隐藏且不生效，切回后恢复勾选状态和名称。「添加后缀」在所有保存方式下均可设置，默认 `-zpic`，文件名示例为 `example-zpic.png`。
- 选择「原文件夹」且未启用子文件夹或后缀时，将替换原图；单图保存和批量开始均需确认，未减小的结果保留原图。其他输出自动避开已有文件，不覆盖同名文件。
- 编辑其他预设不影响当前使用的预设；点击「设为当前预设」可在保存时切换。两页共用「保存 / 取消」，点击「保存」或按 `⌘S` / `Ctrl+S` 一次写入外观及预设并生效；取消、关闭弹窗或 `Esc` 放弃两页所有未保存修改。写入失败时保留草稿及原有配置，修正后可重试。

主窗口仅展示当前预设；选择预设、质量、保存位置、命名规则及新增等操作统一在设置中进行，点击「保存」后生效。「设为当前预设」位于编辑名称旁，无需滚动查找。保存时只有当前压缩参数实际变化才清除单图编码结果；改名或修改其他预设保留当前结果。输出选项变化会重置批量结果，避免沿用旧位置。

右侧「压缩概览」从顶部展示当前预设、质量档位、压缩结果及保存方式，可点击预设旁的「编辑」进入设置。信息区可滚动，状态、保存、取消和打开输出文件夹等操作固定在底部；压缩操作位于顶部操作栏。

## 悬浮窗收图

- 点击主窗口右上角「悬浮窗」打开置顶收图窗口。默认以图片堆叠和数量胶囊展示，拖动顶部空白区域可移动；点击堆叠、数量或右上角箭头展开，左上角关闭按钮收起整个悬浮窗。收起悬浮窗不取消已经接收的任务。
- 展开后可选择图片、切换缩略图网格或列表，并按处理状态筛选、按名称/体积/节省率排序。筛选和排序不影响主窗口；启用状态筛选后，标题显示「匹配数 / 总数」，筛选按钮保持选中提示。选中图片使用蓝色选中提示，键盘方向键可切换，点击底部「预览选中」、双击图片或回车可在主窗口预览。「在 Finder 中显示」定位选中图片，已有压缩输出时优先定位输出文件；「查看队列 / 下载位置」位于底部。左上角返回按钮或 `Esc` 回到堆叠视图，再按 `Esc` 关闭悬浮窗。
- 悬浮窗使用系统半透明模糊材质，不支持材质的平台使用普通背景。展开和收起会保留靠近的屏幕边缘，避免窗口超出当前屏幕；两种视图都支持继续拖图。缩略图与主队列共用有界缓存并按需加载。
- 将本地 JPEG/PNG/WebP 图片、多张图片或文件夹拖入悬浮窗，会加入批量队列并按文件路径去重。即使只拖入一张，也使用队列；主窗口已有单张图片时会一起保留。
- 将浏览器中的 JPEG/PNG/WebP 图片拖入悬浮窗，会读取拖放中的图片地址或图片数据，下载原件后加入队列。支持直接图片链接、浏览器提供的 HTML 图片和 PNG/JPEG/WebP 数据；网页链接、登录限制、站点防盗链、浏览器未提供可读取内容的 `blob:` 图片可能无法下载，窗口会显示原因。
- 网页图片原件保存在系统「下载」目录下的 `Z Pic` 文件夹，点击「下载位置」可打开。下载按实际格式校验，自动避免重名和覆盖；每张仍受 64 MiB、3200 万像素及静态 JPEG/PNG/WebP 限制。压缩在本机完成，只有下载网页图片时联网。
- 压缩、保存、设置或覆盖确认期间收到的拖放会暂存，当前操作结束后依次导入。下载错误和暂存已满的提示会保留到点击「清除提示」，后续成功项不会覆盖错误，悬停可查看最近的失败详情；其他有效图片仍可入队。「取消」中止当前接收，已经下载的原件会保留。

## 批量处理

- **导入队列**：在空视图或批量队列中点击「选择图片 / 添加图片」（可多选）、「选择文件夹 / 添加文件夹」（递归扫描，支持显式选择的目录符号链接，跳过内部隐藏目录/文件及符号链接，单队列最多 2000 张），或将多个文件与文件夹直接拖入窗口；已在批量队列中时拖入或添加会追加并去重。
- **输出方式**由当前预设决定：
  - **原文件夹**：每张图片保存在自己的原文件夹；启用子文件夹时保存在各原目录下的指定子文件夹中，启用后缀时修改副本文件名。子文件夹和后缀均未启用时，请求确认并原子替换原图，未减小的图片不会覆盖。
  - **每次询问**：每次开始、继续、重试或重新压缩时选择输出目录，上次可用目录仅作为选择器的初始位置；取消选择不会启动任务。
  - **固定输出目录**：使用预设保存的目录，目录缺失或不可用时显示错误；可选保存到子文件夹。固定目录与询问目录的输出保留导入的相对路径并应用后缀；同名冲突自动编号，绝不覆盖已有文件。
- **缩略图队列**：图片以缩略图卡片纵向堆叠展示，同时显示文件名、格式、尺寸、状态和压缩前后大小；选中项用蓝色边框标识。缩略图保持原始比例与 JPEG 拍摄方向，随列表滚动按需加载，最多缓存 96 张小图；主窗口和悬浮窗均不再需要的加载任务会取消。缓存被再次请求时，会按两秒检查间隔在后台核对文件身份、大小和修改时间，变化后重新加载；损坏或无法读取的图片显示占位提示，仍可查看错误与移除。
- **并发执行、取消与恢复**：批量任务根据 CPU 数量并发压缩，最多同时运行 6 个编码任务，并与缩略图解码共用 512 MiB 的估算工作内存预算。估算包含图片尺寸、格式、输入与输出缓冲，以及原生编码器开销；单张估算超过预算时独占运行。预算用于控制任务准入，不是整个应用或子进程的实际内存上限。输出文件名按导入顺序预先分配，压缩完成后及时保存，避免小图等待前面的大图。过程中显示本次完成数与百分比，可点击「取消操作」中断；按钮随后显示「正在取消…」，等待当前步骤结束。已完成保存的项会保留结果，可点击「继续压缩」只处理剩余项，或点击「重新压缩」全部重跑。
- **队列筛选、搜索、排序与快速操作**：支持按状态切换「全部 / 待处理 / 已完成 / 失败」，每项显示整个队列的对应数量；在当前状态内按相对路径文件名搜索（`⌘F` / `Ctrl+F` 快速聚焦），搜索旁可按「默认顺序 / 按名称 / 原大小 ↓ / 节省率 ↓」排序（排序和筛选期间会保持当前选中项）。列表头显示当前匹配数量；没有匹配时可点击「清除搜索」保留状态筛选和排序，或点击「显示全部」重置筛选与搜索。输入焦点不在文本框时可按 `Delete` / `Backspace` 快速移除当前选中项；结果摘要会同时显示已节省体积与未减小数量。
- **失败项重试与一键清理**：存在失败或无效图片时，队列顶部会显示失败提示栏——可点击「移除无效项」仅清理损坏/动画 PNG/WebP 等不可重试条目，或点击「移除失败项」清空队列中的全部失败条目（若当前正处于「失败」筛选且已无剩余失败项，会自动切回「全部」视图）；存在可重试的压缩/写入失败项时还会显示「重试失败项」，选中单条失败项或在其单张预览中也会显示「重试」按钮，仅重跑失败项并保留已完成项与待处理项（在「覆盖原图」模式下重试同样需要确认）。
- **单张对比预览**：在队列中点击「预览」或双击队列项（焦点在列表时也可按 `Enter`）进入单图「对比 / 原图 / 结果」预览，支持缩放与拖动对比；右侧显示「当前图片结果」及该图片的实际输出文件，底部可查看失败原因或点击「定位文件 / 移除」。待处理或可重试图片的顶部操作栏提供「压缩此张 / 重试」，也可按 `⌘Enter` / `Ctrl+Enter`，按当前方案及批量输出设置仅处理这一张并返回队列，其他图片保持原状，覆盖模式仍需确认。点击「上一张 / 下一张」或按 `⌘[` / `⌘]`（`Ctrl+[` / `Ctrl+]`）会在当前筛选与排序结果内顺序切换；按 `Esc` 或点击「返回列表」回到队列。
- **失效保护**：切换到压缩参数不同的预设、保存对当前参数的修改，或修改预设输出位置和命名规则时，会清除相应批量结果；重复选择同一预设保留结果。

完成压缩后，预览区默认显示「对比」：左侧原图、右侧压缩后，显示各自文件大小。左右拖动分隔线查看画质变化，也可切换「原图 / 结果」单独查看。分隔线获得焦点后，方向键微调，`Home` 显示完整压缩结果，`End` 显示完整原图。

使用加减按钮（`⌘-` / `⌘=` 或 `⌘+`）、鼠标滚轮或触控板捏合缩放；「1:1」（`⌘1`）按原始尺寸查看，「适应」（`⌘0`）恢复完整图片，对应按钮显示当前选中状态。放大后双指滚动平移，单图模式也可拖动平移。三种模式共用缩放和位置，切换不会影响压缩结果或保存内容。重新压缩或更换图片后恢复居中对比和适应显示；覆盖原图后不再提供旧原图对比。

主界面常用快捷键：`⌘O` 选择或追加图片、`⌘V` 粘贴图片、`⌘C` 在未聚焦文本输入时复制当前压缩结果、`⌘Enter` 开始/继续或重新压缩（批量单张预览中仅处理当前待处理或可重试图片）、`⌘S` 在单图模式下按预设保存结果（在批量「每次询问」队列页可选择输出文件夹）、`⌘,` 打开设置；批量队列页中 `⌘F` 聚焦文件名搜索、未聚焦文本输入时 `Delete` / `Backspace` 移除选中项；批量单图预览中 `⌘[` / `⌘]` 切换上一张 / 下一张、`Esc` 返回队列；预览中 `⌘-` / `⌘=`（或 `⌘+`）/ `⌘0` / `⌘1` 缩放与恢复适应（其他平台使用 `Ctrl`）。处理期间、设置弹窗与覆盖确认框打开时暂停主界面操作。

设置保存在系统用户配置目录的 `z-pic/settings.json`。macOS 默认为 `~/Library/Application Support/z-pic/settings.json`。外观主题统一在「设置 → 通用」中选择，可即时预览「跟随系统 / 浅色 / 深色」，保存后记住选择；外观主题、预设名称、质量参数、保存选项及当前选择均随配置保留，旧版配置直接兼容。旧版收藏标记读取时忽略，下次保存时移除。首次启动无配置时使用默认预设与跟随系统主题；配置损坏时显示错误并暂用默认预设，不自动覆盖原文件；写入失败时保留旧文件和编辑内容。

设置文件在 JSON 解码前拒绝无效 UTF-8 和未配对的 UTF-16 转义，避免名称或输出路径被静默替换；合法 emoji 与转义反斜杠仍正常读取。同一 JSON 对象中的重复字段（包括转义键名和大小写折叠后相同的字段）会被拒绝，避免后值静默覆盖前值。

输入限制为 64 MiB、3200 万像素。压缩不缩放图片，JPEG 会按 EXIF 方向规范化像素，并保留完整合法的 ICC 色彩配置文件（如 Display P3）。结果未变小时保留原始数据并禁用覆盖。“另存副本”始终拒绝覆盖源文件或任何已有文件。JPEG 重新编码及 PNG 有损压缩可能改变或移除其余元数据。JPEG/WebP 转为剪贴板 PNG 时，生成的数据同样限制为 64 MiB；超过限制会显示错误，保留现有剪贴板内容。

“另存副本”的默认名称最多检查 1000 个已有名称，耗尽后提供可编辑建议；名称建议不预留文件，最终保存始终通过排他创建拒绝覆盖。

“覆盖原图”需要单独确认，确认框默认选中“取消”；覆盖后无法通过本工具恢复原文件，不会自动生成备份。保存前会核对源文件与压缩输入是否一致，拒绝覆盖已被外部修改、已删除或指向符号链接的源文件；此时可以重新选图，或另存当前结果。覆盖成功后会更新图片内容快照，保留本次大小对比及另存功能，并禁用同一结果的重复覆盖。

单图压缩使用选图时的内容快照，外部修改原文件不会改变本次处理内容。批量导入仅保留路径与图片头信息，在各项实际执行时重新读取原文件；导入后外部修改的内容可能参与处理，覆盖时仍核对本次实际压缩输入。批量结果预览读取当前原图和实际输出文件，只有内容完全相同时才共用预览。正常关闭应用会等待已经开始的保存操作完成。

覆盖使用原文件所在目录的临时文件，完整写入并同步后替换，保留文件权限；不保留原 inode、属主、扩展属性或硬链接关系。当前 macOS 目标使用同目录原子替换；源文件校验与替换之间仍存在很短的并发修改窗口，不提供跨应用文件锁。写入或替换失败时清理临时文件并保留源文件。

PNG 使用 **pngquant 量化颜色，再由 Oxipng 优化输出**，不提供单独的无损模式。支持透明度和 8/16 位 PNG 输入，但输出颜色、位深、渐变、阴影与半透明边缘可能变化。达不到质量下限或没有体积收益时，不采用量化结果，保留较小且有效的数据。PNG 质量值是 pngquant 的内部评分，不是 JPEG 滑块值或“画质保留百分比”。

WebP 使用捆绑的 **cwebp 1.6.0** 重新编码，输入和输出始终为 WebP，不缩放图片。JPEG 和 WebP 共用方案中的 1–100 质量值，旧设置文件无需迁移；WebP 的 100 仍为有损编码。保留透明度的 Alpha 样本以及支持的 EXIF/ICC/XMP 元数据；不自动旋转 WebP 像素。仅接受静态 WebP，动画文件会明确拒绝，不提取第一帧。输出未减小时保留原始数据；超出编码器单边 16383 像素限制但仍符合输入限制的有效图片也保留原始数据。

WebP 头部检查还读取 VP8/VP8L 实际帧尺寸，拒绝与 VP8X 画布不一致或超过像素上限的输入；检查阶段不分配像素缓冲。

| 初始方案 | JPEG / WebP 质量 | PNG 最低–目标质量 | PNG 最大颜色数 | PNG 速度 |
| --- | ---: | ---: | ---: | ---: |
| 均衡（默认） | 80 | 65–85 | 256 | 3 |

图片质量六档统一控制 JPEG / WebP 质量与 PNG 的质量范围、最大颜色数、处理速度，压缩时使用所选档位的参数，无需分别设置。预设名称不能为空或重复，最长 40 个字符。

切换到压缩参数不同的预设或保存当前参数修改后，旧压缩结果清除并恢复原图预览，需要重新压缩；重复选择和改名保留结果。处理过程中禁止维护预设。没有体积收益时显示“未减小（0.0%）”，工具执行失败时显示错误。

暂不提供动画 PNG/WebP、HEIC、AVIF、GIF、格式转换或调整尺寸。

界面约定见 [DESIGN.md](DESIGN.md)，清理记录与防回归经验见 [LESSONS.md](LESSONS.md)。图片核心位于 `internal/compress`；原生工具执行、输出限制、超时与取消处理位于 `internal/pngtools` 和 `internal/webptools`。JPEG 编码及 PNG 验证使用 Go 标准库，WebP 解码复用已有的 `golang.org/x/image/webp`，PNG/WebP 压缩使用捆绑工具；没有新增 Go 模块或版本。

批处理调度与保存位于 `batch_runner.go`，图片工作内存预算位于 `image_budget.go`；PNG/WebP 共用的原生工具缓存、完整性验证与原子释放逻辑位于 `internal/toolcache`。每次获取工具都重新核对 SHA-256 和完整权限位，拒绝 setuid/setgid/sticky 工具并重新释放；不能用 inode、大小和 mtime 代替内容验证；校验与执行之间仍有同一用户并发改写路径的剩余竞态。`internal/toolio` 提供共用的 32 KiB stderr 缓冲，超过上限继续排空。GitHub Actions 在 macOS ARM64 上执行竞态检测、Go 与 MyGo 静态检查、捆绑编码器验证和构建；编码器的真实集成测试随 `go test -race ./...` 一起运行。

批量导入在单次扫描内缓存成功解析的父目录规范路径，复用前核对目录身份；目录别名改向或目录重命名后重新解析。每次导入独立建立缓存，文件本身的符号链接保留独立路径身份，文件列表的目录识别阶段也逐项检查取消。

批量输出规划记录已预留名称的后继编号，重复名称跳过连续预留的编号，避免从头逐个检查。记录只在单次规划内使用；磁盘已有文件、目录、符号链接与源文件路径的冲突仍重新检查，失败任务不占用名称，输出命名保持任务顺序。单个输出最多考虑 10,000 个候选，耗尽后提示更换目录或名称；实际保存通过独占创建拒绝覆盖已有文件，空结果不会创建输出。

输出相对路径按实际路径分量判断是否越界，保留 `..photo.jpg` 和 `.../photo.jpg` 等合法名称。规划阶段解析已有子目录的符号链接，拒绝指向所选目录之外的路径及悬空链接；启用预设子文件夹时也检查这一边界。所选根目录本身可以是别名，目录内的别名也可使用；缺失的普通子目录仍在保存时创建。该检查不锁定目录，无法消除规划结束后其他进程更换目录的并发窗口。

拖放或粘贴的一次导入共用 `dropimport.Resolver`，按顺序处理图片，记录本次成功保存的名称与后继编号，减少同名图片重复尝试硬链接的开销。记录仅在本次导入内使用；其他文件、目录和符号链接仍重新检查，外部占用释放后可再次使用。失败、取消与本地文件路径不预留下载名称，图片仍完整解码校验，实际落盘仍通过硬链接或独占创建拒绝覆盖。下一次导入会重新建立记录，HTTP 连接继续由调用方传入的 transport 复用和管理。

拖放文本解析按需逐行遍历，省去整体 CRLF 替换与临时行切片；文本表示只转换一次，HTML 直接从字节读取，未提供 HTML 时省去分词器与基准地址查找。只有 `file:` 开头的行进入文件 URL 解析，其余行直接按本地路径检查。HTML 声明图片后不会读取不适用的文本 provider，必要时直接采用 PNG/JPEG/WebP 备用数据。一次拖放或粘贴在去重前最多接受 2000 个有效原始引用，所有原生条目共享预算；超限拒绝整次导入并停止后续 provider，队列容量则继续按实际新增记录计算。实际导入使用 `ParseContext`，provider 调用前后与列表/HTML 遍历检查取消；已执行的同步 provider 需等其返回。

文件、解码和下载读取共用 `internal/contextio` 的取消适配器。压缩、缩略图和单图预览共用 `internal/imageinput` 读取文件内容，按已打开文件的大小预分配缓冲区，减少逐步扩容带来的分配和复制。读取期间文件增长或截短时以实际读取内容为准，增长后仍按实际字节数执行 64 MiB 上限，并检查取消。

文件增长时，读取器只扩展同一份内容缓冲，先探测 EOF 再扩容，避免额外保留完整尾部副本，扩容大小最多为 64 MiB 加一个超限探测字节。无需缩小的缩略图直接采样一次，保持预乘 Alpha、16 位转 8 位的舍入、方向和独立存储。未减小结果的覆盖快照复用输入哈希，仍记录输入和输出的各自长度；较小输出仍独立计算哈希。

压缩与剪贴板转换的图片头读取、JPEG 像素解码会逐次检查取消；JPEG 编码前的 EXIF 方向转换在内部逐行检查取消，JPEG 编码写入阶段同样逐块检查取消并在达到原图字节预算时提前中止编码，不发布部分图像。剪贴板 PNG 编码在每次输出写入时检查取消和大小上限，失败数据不会写入系统剪贴板。下载使用共享有界空闲连接池和连接、TLS、响应头超时，响应头限制为 1 MiB，跨次网页导入继续复用连接，并拦截从公网地址重定向到本地回环或内网地址的请求；响应前缀不属于 JPEG/PNG/WebP 时，直接中止接收并避免创建临时文件，合法图片仍经过完整容器与像素校验，不信任服务器声明的 MIME 类型。

PNG 量化和无损优化均保留含 `caBX`/`iDOT` 的文件原始字节，元数据扫描逐块响应取消。PNG 工具输出先与输入逐段比较，相同前缀复用原数据，首次不同后才分配候选缓冲；输出达到输入长度时释放候选缓冲，继续排空并统计后续输出。64 MiB 上限按实际接收字节数检查，工具失败、超时、取消和超限仍按原有规则处理。

WebP 压缩使用 `webptools.EncodeSmaller` 接收工具输出，达到原图长度时释放候选缓冲，继续排空输出并执行 64 MiB 上限、退出状态与取消检查。工具成功但输出未减小时，直接复用原始输入切片；调用方须保持输入不变，压缩流程仍完整解码原图以校验数据。`webptools.Encode` 继续返回完整编码结果，供需要较大输出的调用方使用。

单图压缩使用 `compress.BytesWithPreview`，将 PNG/WebP 输出完整校验时解码出的像素直接用于预览，避免再次解码。JPEG 预览仍从实际压缩结果解码，保持导出方向与预览一致。未减小的结果复用原图位图；批量压缩使用 `File`/`Bytes`，结果对象只保存编码数据，不保留预览像素。PNG 输出解码也会在读取数据时检查取消。

EXIF 方向包装保留原图的 `Opaque` 判断能力，JPEG 转成剪贴板 PNG 时直接复用原图的不透明状态，省去逐像素重复扫描及颜色接口分配。包装不新增完整像素缓冲区；没有 `Opaque` 接口的图像仍逐像素检查真实 Alpha，包括 16 位 Alpha。

JPEG 重新编码时，方向变换对零原点、宽高均为偶数的 4:2:0 图像保留色度采样，每个 2×2 像素块只搬运一组 Cb/Cr，减少方向缓冲的分配。奇数尺寸、其他坐标原点或采样方式沿用完整色度映射，保留边缘像素；回归测试同时核对各方向的 Y/Cb/Cr 样本与 JPEG 编码字节。

YCbCr 与灰度方向变换根据方向计算起点，用固定索引步长推进像素，省去逐像素重复解析方向与图片边界。转置类方向按 32×32 分块复制，改善按列读取源像素时的缓存局部性；对零原点、宽高均为偶数的 4:2:0 图像，色度平面也直接按步长复制。其他色度布局仍按源采样方式读取，支持非零原点、带行填充的子图和单行、单列图片。

JPEG 编码输出达到可用体积上限后，立即释放候选缓冲并提前终止编码，避免继续为最终不会采用的数据执行编码与扩容；小于原图的结果保留完整编码字节（含合法 ICC 色彩配置文件），未减小的结果仍返回原始数据。

`BenchmarkReadInputJPEG12MP` 单独测量文件读取，`BenchmarkThumbnailFileJPEG12MP` 覆盖完整文件读取、JPEG 解码和缩略图生成；当前解码器仍会解码全尺寸图片。Go benchmark 的内存分配统计不包含原生子进程或 GPU 资源，不能作为应用峰值内存。

`BenchmarkValidatedPNGPreview12MP` 对比 PNG 输出校验后再次解码与直接复用校验像素两种路径。Apple M1、Go 1.27.3 下，4000×3000 合成图片使用 `-benchtime=10x -count=3` 测得约 231–233 ms/op → 115–118 ms/op，分配量约 96.2 MB/op → 48.1 MB/op。该数据只覆盖输出校验与预览解码阶段，不包含原生编码、界面位图转换或绘制，也不代表完整压缩流程的提速比例。

`BenchmarkClipboardJPEG12MP` 将 4000×3000 合成 JPEG 转成剪贴板 PNG，分别测量 EXIF 方向 1 和 6。Apple M1、Go 1.27.3 下，使用 `-benchtime=3x -count=3` 测得方向 6 优化前后约 1.21–1.22 s/op → 0.98–1.03 s/op，Go 累计分配量约 106.3 MB/op → 67.9 MB/op，分配次数约 2400 万次/op → 1200 万次/op；方向 1 的累计分配量均约 67.9 MB/op。基准包含 JPEG 解码、方向处理和 PNG 编码，不包含系统剪贴板写入或界面操作，分配量不代表峰值内存。

`BenchmarkOrientYCbCr42012MP` 单独测量 4000×3000 的 4:2:0 图像按 EXIF 方向 2 镜像和方向 6 旋转；`BenchmarkJPEGCompression12MP` 将同尺寸、质量 90 的合成 JPEG 以质量 80 重新压缩，包含图片头检查、JPEG 解码、方向处理、编码及结果快照。Apple M1、Go 1.27.3 下，使用 `-benchtime=3x -count=3` 测得：两种方向变换的 Go 累计分配量均约 36.0 MB/op → 18.0 MB/op；完整旋转压缩约 62.5 MB/op → 44.5 MB/op，减少约 29%，方向 1 均约 26.5 MB/op。基准不包含文件读取、保存、界面预览或剪贴板转换，累计分配量不代表峰值内存。

坐标推进优化使用 `go test ./internal/compress -run '^$' -bench 'BenchmarkOrientYCbCr42012MP|BenchmarkJPEGCompression12MP' -benchmem -benchtime=3x -count=3 -cpuprofile=/tmp/z-pic-orientation.cpu` 对比前后。在相同 Apple M1、Go 1.27.3 环境下，镜像方向变换约 50.5–52.3 ms/op → 16.7–18.4 ms/op，旋转方向变换约 55.6–71.7 ms/op → 24.7–33.3 ms/op，累计分配量仍约 18.0 MB/op。测试逐像素核对方向 2–8 的 Y/Cb/Cr 样本，并比较完整 JPEG 编码字节；另覆盖带行填充和非零原点的灰度子图。耗时受 CPU 与缓存状态影响，此处收益只对应方向变换阶段，不能直接作为完整压缩流程的提速比例。

分块复制与色度步进优化沿用上述两个基准，使用 `-benchtime=5x -count=3` 对比前后。在 Apple M1、Go 1.27.3 下，12MP 镜像方向变换约 16.3–17.1 ms/op → 7.9–9.2 ms/op，旋转方向变换约 22.3–24.7 ms/op → 10.8–12.4 ms/op，累计分配量仍约 18.0 MB/op。新增回归场景跨越 32 像素分块边界，同时覆盖奇数尺寸、带行填充和非零原点的 YCbCr/灰度子图，并逐样本核对全部方向和 YCbCr 的完整 JPEG 编码字节。这里仅报告方向变换阶段的收益；完整压缩还包含 JPEG 解码、编码与结果校验。

`BenchmarkJPEGNoSavings12MP` 将 4000×3000、质量 30 的合成 JPEG 以质量 100 重新编码，分别测量 EXIF 方向 1 和 6，并确认结果仍复用原图字节。Apple M1、Go 1.27.3 下，使用 `-benchtime=3x -count=3` 测得 JPEG 输出缓冲优化前后：方向 1 的 Go 累计分配量约 34.9 MB/op → 22.3 MB/op，减少约 36%；方向 6 约 52.9 MB/op → 40.3 MB/op，减少约 24%。同期 `BenchmarkJPEGCompression12MP` 的较小结果仍分别分配约 26.5 MB/op 和 44.5 MB/op。基准覆盖图片头检查、JPEG 解码、方向处理、编码与结果快照，不包含文件读取、保存或界面预览；只据此报告分配量收益，不代表峰值内存或编码提速。

`BenchmarkScanBatchPaths1000Files` 使用 10 个子目录中的 1000 张 32×24 合成 JPEG，对比文件夹递归导入和直接导入文件列表。Apple M1、Go 1.27.3 下，使用 `-benchtime=5x -count=3` 测得父目录缓存优化前后：文件夹扫描约 52–65 ms/op → 25–28 ms/op，文件列表扫描约 40–44 ms/op → 26–27 ms/op；Go 分配量约 24.8 MB/op → 20.5–20.6 MB/op。该基准只覆盖扫描与头部检查，不解码像素或执行压缩，耗时也受目录结构和文件系统缓存影响。

`BenchmarkPlanBatchOutputs1000Files` 为不同源目录中的 1000 个文件规划输出，分别使用唯一名称和相同名称，目标目录初始为空。Apple M1、Go 1.27.3 下，使用 `-benchtime=1x -count=3` 测得同名场景优化前后约 6.96–7.01 s/op → 37–40 ms/op，Go 累计分配量约 2.10 GB/op → 10.5 MB/op；唯一名称场景约 36–37 ms/op → 37–43 ms/op。该基准只覆盖路径规划与文件系统检查，源文件内容不参与处理，不包含图片扫描、解码、压缩或保存；分配量是单次操作的累计值，不是峰值内存。

`BenchmarkResolve1000Images` 从本机 HTTP 测试服务器依次导入 1000 张 32×24 合成 PNG，分别使用唯一名称和相同名称，目标目录初始为空。Apple M1、Go 1.27.3 下，使用 `-benchtime=1x -count=3` 测得同名场景优化前后约 86.9–89.3 s/op → 447–450 ms/op，Go 累计分配量约 317.9 MB/op → 100.4 MB/op；唯一名称约 453–488 ms/op → 453–483 ms/op，分配量约 100.0 MB/op → 100.1 MB/op。基准覆盖 HTTP 下载、临时文件、完整图片校验、命名与保存，分配量包含进程内测试服务器的开销，不包含真实外网延迟、后续队列扫描、压缩或界面操作，也不代表峰值内存。缓存只跳过本次成功保存的名称，目标目录已有大量同名文件时仍会重新检查这些外部占用。

`BenchmarkParse2000Images` 使用内存中的 `transfer.Bytes` 表示解析 2000 个输入，文件和 URL 列表使用 CRLF 分行。Apple M1、Go 1.27.3 下，使用 `-benchtime=500x -count=3` 测得优化前后如下：

| 输入表示 | 耗时 ms/op，优化前 → 后 | Go 累计分配 MB/op，优化前 → 后 |
| --- | --- | --- |
| 本地文件路径列表 | 0.835–0.967 → 0.441–0.464 | 1.620 → 1.133 |
| 文件 URI 列表 | 0.846–0.930 → 0.744–0.784 | 1.661 → 1.454 |
| HTTP URL 列表 | 1.638–1.663 → 0.854–0.880 | 2.736 → 1.535 |
| 纯文本 HTTP URL 列表 | 1.441–1.489 → 0.870–0.884 | 2.397 → 1.535 |
| HTML 图片标签 | 2.089–2.113 → 2.048–2.072 | 2.212 → 2.089 |

该基准只覆盖表示读取、文本解析和去重，不包含系统拖放或剪贴板读取、网络下载、文件扫描、图片解码或压缩；累计分配量不代表峰值内存。时间受 CPU 状态影响，HTML 场景的主要变化是减少文本副本。

`BenchmarkPNGOutputBuffer` 使用 6 MiB 合成输入，分块接收不同大小的输出。Apple M1、Go 1.27.3 下，使用 `-benchtime=20x -count=3` 测得 Go 累计分配量：原样输出约 16.78 MB/op → 0.033 MB/op，24 MiB 不同内容输出约 67.11 MB/op → 16.78 MB/op；同体积但内容不同的输出均约 16.78 MB/op，4 MiB 不同内容的较小输出均约 8.39 MB/op，1 KiB 小输出均约 0.034 MB/op，没有按输入体积预分配。`BenchmarkCommandOutputFallback6MiB` 让测试子进程原样回传 6 MiB 输入，覆盖实际管道及回退处理，分配量约 16.81 MB/op → 0.070 MB/op。两项基准只测输出接收与缓冲，不运行原生 PNG 编码器，也不包含 PNG 校验或界面操作；累计分配量不代表峰值内存。

`BenchmarkWebPOutputBuffer` 使用 6 MiB 合成输入，对比保留完整输出与仅保留较小结果两种缓冲方式。Apple M1、Go 1.27.3 下，使用 `-benchtime=10x -count=3` 测得 24 MiB 输出的 Go 累计分配量约 67.11 MB/op → 16.78 MB/op，减少约 75%；两种方式接收 1 KiB、4 MiB 和 6 MiB 输出时均分别约 0.034、8.39 和 16.78 MB/op。`BenchmarkCommandLargerOutput24MiB` 使用测试子进程读入 6 MiB 输入、输出 24 MiB 数据，覆盖实际管道与原图回退，宿主进程累计分配量约 67.15 MB/op → 16.81 MB/op。两项基准只测输出接收与缓冲，不运行原生 WebP 编码器，也不包含图片解码、校验、预览或子进程分配量；累计分配量不代表峰值内存或原生编码提速。
